# Acceptance Criteria

## UI
- app follows DESIGN.md
- layout feels premium and calm
- all cards use consistent radius
- typography hierarchy is clear
- no cluttered screen composition

## Navigation
- bottom navigation works
- nested routes work
- booking flow is complete
- auth flow is separated from main app

## Booking
- user can select a class
- user can select schedule
- credit check is shown
- booking confirmation is displayed
- QR code confirmation exists

## Membership
- package list is visible
- package detail is clear
- remaining credit is visible
- active package is shown

## Profile
- member information is visible
- booking history is accessible
- logout is available

## Code Quality
- no giant widgets
- reusable components are used
- no direct API calls inside UI widgets
- theme constants are centralized
- state management is separated by feature
